# 2026-08-30 の証拠

## codex-ota-logging-review.txt — OTA の要求ログに対する Codex の敵対レビュー(逐語)

`codex exec --sandbox read-only` の**全出力**(ヘッダ込み)。`ota-server-per-request-logging`
の SHIP-GATE が要求した外部相談の成果物で、`loop-replan-gate.sh arsenal-receipt` が
この file の sha を記録している。

★**なぜ `.md` ではなく `.txt` か**(2026-08-30、門に止められて判った):
最初 `.md` で置いたら `doc-linerefs` が止めた —— Codex の出力は当然コードを行番号で引くので、
「書類の行番号引用を増やしていない」に当たる。あの門の狙いは**人が書く書類**が腐る事の防止で、
実測(2026-08-05)では人が読んだ 33 件のうち 13 件が既に別の場所を指していた。

ここで門に除外を足すのは、`doc-linerefs.test.mjs` の註が名指しで戒めている
「自分が詰まった時に門を緩める形」そのもの。そして**行番号を消せば逐語記録が偽物になる**。
だから直したのは門でも中身でもなく**置き場の形**: 外部ツールの凍った出力は書類ではなく記録で、
`.txt` がその実体に合っている。以後、逐語の証拠は `.txt` で置く。

指摘の中身と、それをどう直したかは commit メッセージ側に在る(此処では要約しない ——
2箇所に書くと必ず片方が腐る)。
