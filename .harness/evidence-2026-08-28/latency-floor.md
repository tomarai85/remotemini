# 机側の遅さは床に着いた (2026-08-28)

次に此のレーンへ来る者へ: **`/api/account` が遅いという話を追い掛けない事**。
私は今日2回それを追い掛け、2回とも実測で外した。

## 何を追い掛けたか

`/api/account` が 1062ms を出す行をログで見て、「初回だけ 1 秒掛かる」と読んだ。
続けて「60 秒放置すると 0.65s に戻る」も見て、**放置後の罰がある**と結論しかけた。
どちらも、それらしい機序まで書けた(子プロセスの起動がページキャッシュから落ちる)。

## 実測(静かな時に、複数回)

放置 75〜90 秒を挟んで3回ずつ:

```
試行1  口座 冷 0.197s  温 0.150s  | 一覧 冷 0.069s
試行2  口座 冷 0.197s  温 0.213s  | 一覧 冷 0.083s
試行3  口座 冷 0.192s  温 0.141s  | 一覧 冷 0.064s
```

**罰は無い。** 冷と温の差は測定の揺らぎの中に居る。

`/api/sessions` を同じ手順で3回測った時も 0.101 / 0.112 / 0.111s で、
最初に見た 0.63s は再現しなかった。

## では 1.05s / 1.25s / 0.65s は何だったか

**机が混んでいた瞬間**。それらを観測した時、私は同じ機体で
live-* の検査(使い捨ての会話を建てて Claude を起こす)・1.8MB の scp・
`npm test` を並行させていた。健全性の常駐(`com.fleet.rc-health-observer`、
600 秒ごと)も同じ機体に居る。

## 今の実力(静かな時)

| 経路 | 実測 |
|---|---|
| `GET /api/sessions` | **0.06 - 0.11s** |
| `GET /api/account` | **0.14 - 0.21s**(内 0.16s は `fleet-account-cswap.sh` の起動) |

口座の欄は工具帯に在って自分の `.task` を持つので、**一覧を一度も塞がない**。
どちらも Nielsen の 1 秒の内側。**此処は床**。

## 床の意味

机側の待ち時間を更に削る作業は、此のレーンでは**もう価値を生まない**。
今日の始めに在った本物の遅さ(一覧 533ms、口座の同期呼び出しが event loop を
180ms 塞ぐ、prewarm が 483ms 塞ぐ)は全部潰した。
残っているのは測定の揺らぎと、子プロセス1回分の 0.16s だけ。

★次の的は Tom が名指しする物。**私が「まだ速くできる」を発明しない。**

## 方法として残す物

★**1回の測定で機序を書かない。** 今日、同じ型で2回外した:
  1つ目は「口座の中断 37.5%」を製品の欠陥と読んだ(実際は私の install の巻き添え)。
  2つ目は此処。どちらも**それらしい機序まで書けてしまった**のが危ない所で、
  説明が付く事は観測の代わりにならない。
★**混んでいる機体で測らない。** 自分が走らせている物を数えて、静かになってから測り直す。
