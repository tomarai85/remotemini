# 画面を描く file と、其れを測る検査が繋がっていなかった(2026-09-08)

## 何が起きたか

9/7 の UI 作り直し(案 A–H)を「電話の単体 全件 緑」と報告して出荷した。**其の緑は単体の緑**で、
画面を実際に描いて測る UI 検査(XCUITest)は一度も走っていなかった。9/8 に自分で全部走らせたら
**1130 件中 8 件が赤**。全部 9/7 に触った所で、内 4 つは独立した欠陥だった。

| 赤くなった検査 | 何が壊れていたか | 分類 |
|---|---|---|
| `TapTargetUITests` × 3 | 停止ボタンの的が **30pt**(下限 44pt)。`.tapTarget()` を落としていた | 製品の欠陥 |
| `ConversationUITests` × 1 | 停止ボタンが**存在しない**。「机が動いている時だけ出す」に変えた = 選択待ちで止める手段が消える | 製品の欠陥(能力の後退) |
| `InFlightUITests` × 1 | 鍵を押すと入力欄が伏せられ、其の「入力できません」が「送っています…」を押し退けて**無言**(§2.56) | 製品の欠陥 |
| `TapTargetUITests` × 1 | 帯を 1 本に畳んだ時、時刻の識別子 `conversation.lastReadableAt` ごと文に溶かした | 製品の欠陥(読み上げ) |
| `AttachButtonUITests` × 2 / `AttachFileButtonUITests` × 1 | 添付を `+` の menu へ畳んだ(**意図した変更**)。検査が畳む前の形を見ていた | 検査の追随漏れ |

停止ボタンの 2 件は特に重い: **一番急いでいる時に押す物**が、小さくなり、選択待ちでは消えていた。

## 何故 commit の門を素通りしたか(実測)

門は「触った file に紐づく対照」を回す(`controls-for:` 行)。測った結果:

```
TapTargetUITests:       対照 0 本
InFlightUITests:        対照 0 本
AttachButtonUITests:    対照 0 本
ConversationView.swift を controls-for に持つ対照 = 3 本
  bar-material-control            … XCUITest を回さない
  conversation-landing-stress     … ConversationUITests(着地位置の負荷試験)だけ
  inflight-sentence-control       … RemoteMiniTests/… = **単体 class のみ**
```

つまり **画面を描く file を触っても、画面を描いて測る検査は 1 本も回らない**。あの 3 class が走るのは
`bash tools/build.sh --sim`(全件)を人が手で叩いた時だけで、門はそれを起動しない。
9/7 の私は単体の緑を見て「緑」と言った —— 門も同じ物しか見ていなかったので、誰も気付かなかった。

★同型の再発である事: 9/7 にも「停止ボタンが何処にも存在しないのに全検査が緑」を踏み、
`.harness/evidence-2026-09-07/` に「描画に触れない検査は『描かれない事』を検出しない」と書いた。
其の時の対策は**私の注意**だった。注意は 1 日で破れた。今度は門へ降ろす。

## 直した物(製品)

1. 停止ボタン: 常に描く(押せるかは `canInterrupt` が決める、2026-08-29 の裁定の通り)+ `.tapTarget()` 復帰。
2. 急ぎの順を変更: **送れない事実 > 今飛んでいる操作 > 出来ない理由 > 直前の答え**。
   「今」は「なぜ」より先 —— 伏せられた理由は、押した操作が作っている事が多い。
3. 席を失った「出来ない理由」は捨てず、状態の行を開くと出る(押せない control の説明を消さない)。
4. 帯の詳細に識別子を戻した(`detailIdentifier`)。時刻を持つ 2 段だけ。
5. 添付の検査を今の形へ(入口を開いてから項目を見る)。畳む前の主張 —— 送信ボタンと離れている /
   読み上げの名前が「何の添付か」を言う —— は入口と項目へ割り当て直した。

## 残す規則

**画面を描く file を触ったら、画面を描いて測る検査が回る事**。
其れを門で保証する対照を `ios/tools/composer-surface-control.sh` に置く(次の commit)。
