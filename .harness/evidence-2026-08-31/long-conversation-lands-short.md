# 長い会話が「最新の3行手前」で止まる —— 断続的な赤の正体(2026-08-31、実物を捕獲)

## 何が判ったか

`ConversationUITests.testOpeningALongConversationLandsAtTheNewestLine` の断続的な赤は
**検査の欠陥ではなく、実物の欠陥**だった。今朝 仕込んだ失敗時の記録が初めて発火し、
倒れた瞬間の画面が取れた。

```
conversation.loadEarlier   exists = true      ← 画面は正常に出ている
conversation.composerField exists = true
line 031 exists = false
line 090 exists = false                        ← 最新の行が**存在しない**

ScrollView            {{0.0, 110.0},  {375.0, 501.7}}
  内容 Other          {{0.0, -2430.7},{375.0, 3308.0}}
実在した行: line 068 … line 087(20 行)
```

## 読み方

- 内容の高さ **3308**、可視 **501.7**、寄せ **-2430.7**
  → 見えている範囲は内容の y ∈ [2430.7, 2932.4]
  → **下端まで 375.6pt 残っている**(= おおよそ 3 行ぶん)
- 実在する行は **068〜087** で止まり、**088/089/090 は作られていない**
  (`ScrollView` は窓の外の行を materialize しないので、`exists=false` は
   「其処まで寄っていない」の別表現)

つまり「開いたら一番新しい行へ寄る」動きは**走っているが、最後まで届いていない**。
画面も履歴も正常で、**寄せ先だけが 3 行手前**。

## 何故 断続的か(仮説、まだ測っていない)

寄せ先を決める時点の内容の高さと、寄せ終わった後の高さが違うと此の形になる ——
遅れて足される物(ライブの行 / 合成の帯 / 入力欄の余白)が在ると、
其の分だけ「一番下」が下へ動き、先に計算した寄せ先が手前に取り残される。
早い機械では layout が先に終わるので当たらない = 全掃きの中(混んでいる時)だけ倒れる、
という観測とも整合する(単体 3/3 緑・class 単独 緑・全掃き FAIL/FAIL/PASS/PASS/PASS)。

★之は**仮説であって観測ではない**。次に確かめる事:
1. 寄せの実装が「id を指して一度だけ」か、「落ち着くまで追う」か
2. 内容の高さが寄せの後に変わっているか(2回 測って差を見る)
3. 3 行ぶん(≈375pt)が**何の高さ**と一致するか(入力欄? 帯?)—— 一致すれば犯人が名指せる

## 何を巻き込んでいたか(此の欠陥の costs)

`ios/tools/conversation-ui-control.sh`(会話画面の変異対照)は**基準の走行が緑でないと
何も測れない**造り。此の赤が基準を落とすので、対照は
`PASS 0 / FAIL 0 / UNMEASURED 1` を返す —— **会話画面の4つの主張を守る対照が丸ごと死ぬ**。
2026-08-31 の全掃きで実測(其の 79 秒の走行が此の記録を残した)。

## 利用者から見た形

長い会話を開くと、**時々 最新より 3 行手前に着地する**。其の 3 行は描画すらされていない
ので、指で送るまで見えない。**配布中の 116 にも、其の前の 105 にも同じ経路が在る**
(2026-08-31 の commit で `git diff` により確認済み: `ios/Sources/Screens/Conversation` は
105 → 116 で 0 file 変更)。
