## 3. 捨てた案 —— 「変わった面の変異だけ回す」(2026-08-12、Codex に否定された)

各変異は `probe` の第3引数で自分の対象 file を宣言しているので、staged な file に
関係する変異だけ回せば良い、と考えた。実測でも `Provisioning.swift` 1文字で **20 → 2**、
所要 **725 → 113 秒**まで落ちた。

**否定された理由(観測で確認済)**: 変異の sed 対象は**欠陥を注入する点**であって、
**同じ欠陥が発生し得る file の集合**ではない。

- 実例: `ios/Sources/Core/Provisioning.swift` は `SeedDigest` / `UserDefaultsSeedLedger` /
  `BundleProvisioning` を抱えている(`grep` で確認)。其処の1行が M13-M16/M20 の測る
  欠陥(= #64 そのもの、初回起動が鍵入力画面に戻る)を混入できるのに、file で選ぶと
  M18/M19 しか選ばれない。
- 同型: `KeyEntryViewModel.swift` の変更が M11/M12(footer / `.disabled`)の欠陥を
  混入できるのに、選ばれるのは M7/M10 だけ。

健全にするには「継ぎ目」を変異ごとに宣言する事になり、其れは**黙って古くなる2本目の
一覧** —— 此の repo が6回踏んだ再発の型(`rc-backend/tools/pre-commit-gates.sh` の頭に
全部書いてある)。作らないと決めた物なので、狭めるのをやめた。

★一般則として残す: **選り分けの鍵は「変更した file」ではなく「欠陥が発生し得る面」。
両者が一致しない検査を file で絞ると、緑の分母が黙って痩せる。**

## 4. 採った案 —— commit では変異を繰り延べる

### 規則(3つだけ。staged の中身で変異を選り分けない)

**繰り延べない**(全20本を回す) — 1つでも当たれば:
- `RC_STAGED_FILES` が空 / 未設定(= 手叩き・全掃き)
- 対照そのものが staged(= 其の commit の目的が計器の証明。繰り延べたら証明が消える)
- `ios/project.yml` / `ios/tools/build.sh` が staged(= 全変異のビルドに効く)

**繰り延べる**(基準だけ回す): 上記以外。

### 繰り延べは「緑」ではない
毎回、繰り延べた変異を**名前で**印字し、「回していない = 緑ではない」と断り、
閉じる手(単体起動 / `run-controls.sh --all`)を出力に書く。
同じ形が既に此の repo に在る(`staged-controls-gate.sh` の edith 側の対照)。

### 空いた穴と、同じ変更で引いた代わりの経路
繰り延べは「出荷の前に全部回す」を機械が強制しない穴を空ける。記憶に懸けた守りは
1日で戻る(此の repo が 2026-08-06 に実測)。だから:
- 全20本が緑だった走行だけが**印**を置く(`ios/build/.mutation-sweep-stamp`、追跡外)。
  印の中身は其の時に測ったバイトの digest —— commit の sha ではない(汚れた木の走行を
  「其の commit で緑」と読ませない)。
- `ios/tools/build.sh` が電話へ入れる直前に印を読み、無い / 古いなら**警告**する。
  ★**門ではない**(裁定「門をもう増やさない」)。止めるかは人が決める。
