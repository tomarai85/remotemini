### PII 検査(8/01 に範囲を広げ、対照を7枚にした)

commit 直後に履歴を掃いて分かった事: 伏字化は fixture にしか効いておらず、**同じアドレスが
`DESIGN.md` §8-3 の本文に全 commit 分残っていた**。検査が `test/fixtures` しか見ておらず、
検査の目的(「remote を付けた瞬間に開示になる」)に対して**範囲が狭かった**。広げた。
広げて更に見つかったのが「push が運ぶのは作業ツリーではなく履歴」で、第2段(全 commit
走査)を足した。**直している最中に自分で新しい常時緑を作った**(下表 C6)。

| 対照 | 期待 | 負の対照(見張りを外すと) |
|---|---|---|
| C1 伏字と ssh 宛先だけ | 緑(= **緑になれる**事) | — |
| C2 本物1件 | 赤・その1件を名指し | — |
| C3 同一ファイルに混在 | 赤・**本物だけ**名指し | — |
| C4 履歴だけに残る | 赤・**履歴として**報告 | **緑(見逃し)** |
| C4b その時の作業ツリー欄 | 出さない(綺麗な物を赤と言わない) | — |
| C5 未追跡ファイル | 緑(誤検出で無視される様にしない) | — |
| C6 **git repo の外** | **exit 2**(緑でも赤でもなく判定不能) | — |
| C7 `git grep` がエラー | **exit 2** | **緑(見逃し)** |
| C8 `git ls-files` がエラー | **exit 2** | **緑(見逃し)** |
| C9 HEAD 未生成・ref には本物 | 赤・**履歴として**報告 | **緑(見逃し)** |

負の対照の意味: 該当の見張りを外した版を同じ木に当てると C4/C7/C8/C9 は緑になる。
つまりこの4枚が赤なのは新しいコードが効いているからで、たまたま通っているのではない。
**「対照が通った」ではなく「対照が識別できる」まで見る**。
C6 が要るのは `cd "$(git rev-parse --show-toplevel)"` が git 失敗時に `cd ""` = bash では
成功してその場に留まる為。`git ls-files` も空を返すので、**本物が目の前にあっても
「なし」で exit 0**。`verify-on-edith.sh` は `.git` を除いて rsync するので、
edith では必ずこの形で走るところだった。C7/C8/C9 は同じ読みで diff を読み直して出た
別の入口 — エラーを「一致なし」と同じ扱いにしていた(C7/C8)、履歴段の入口を HEAD で
書いていた(C9。`git checkout --orphan` 直後の様に **HEAD が未生成でも ref には commit が
ある**木で履歴段を丸ごと飛ばす。push が運ぶのは ref であって HEAD ではない)。

★**現在この検査は exit 1 を返す**(作業ツリー3ファイル + 履歴35箇所 = §8-3 のアカウント
2件)。これは不合格ではなく**未決**。伏字にしないのは、そこでのアドレスが偶然の写り込み
ではなく「edith をどちらのアカウントで走らせるか」という決定の中身だから。remote を
付ける時に §8-3 ごと消すか local only を選ぶかを決める。現状 remote 無し = 実害ゼロ。

## ★この検査の最大の発見: 道具そのものが盲だった

**edith 側でこれまでに出した変異結果は、一度も何も測っていなかった。**

`node:test` の要約行は Node の版で書式が違う — **Node 22 = `# fail 0` / Node 25 = `ℹ fail 0`**。
台本は落ちたかを `"# fail 0" not in stdout` で判定していたため、edith(Node 25)では
その文字列が**原理的に現れず、全変異が無条件に「検出」**になっていた。exit 0 で緑を出し続けていた。
前回の handoff に書いた「変異 M1-M23 も両機で全検出」は**嘘**(訂正済み)。

発見経路は**逆向きの警報**。同一の木に対して edith だけが M2/M6/M26 を「検出」と言い、
MBP は「未到達」と言った。同じコードで結果が割れる以上、差分はコードでなく道具にある。
両機で `node --test` の要約行を直接撮って確定した。

直しは正規表現の追加では終わらせなかった(書式はまた変わり、その時もまた静かに全部緑になる):

1. 判定の正は**終了コード**。要約行は読めた時だけ突き合わせ、食い違えば止める。
2. 測る前に**対照を2枚**回す — 無変異の木が**緑**、故意に壊した木(`src/inject.mjs` 先頭に
   `throw`)が**赤**。どちらか外れたら結果を出さず中断する。
3. 要約行が無い時の扱いを**非対称**にした。`exit != 0` で要約なし = 途中で死んだ(赤で確定)。
   `exit == 0` で要約なし = **緑を名乗っているのに中身が読めない** = 今回 edith を盲にした形
   そのものなので止める。

**対照が最初に捕まえたのは、私がその場で書いた直しの欠陥だった**。対照2の canary は import 時に
e2e を殺すので要約行を一行も出さない。最初の実装はそれを一律 fatal にしており、
「落ちるはずの木が落ちた」だけの正常事を異常として中断した(= 上の 3 がまだ無かった)。
**対照を入れた1回目で、対照が対照読み取り側のバグを出した。**

一般化: 「Node の書式が変わった」は表層。本質は **赤を見分けられることを自分で証明しない検査道具は、
黙って全部緑を出す**。7/31 の「緑は守りが働いている証明ではない」が、今度は**道具の層**で再演した。

### 同じ型がもう1つ: 証拠を出す台本が証拠を捨てていた

直した台本を edith で回したら表が **10行しか出なかった**。`verify-on-edith.sh` が変異段階を

盲だった時の edith は M2/M6/M26 を「検出」と言っていた(到達しない変異が検出される
はずがない = 逆向きの警報)。直した後は MBP と同じく「未到達」と言う。
道具が版に依存しなくなった事を、**両機の表が一致するという形で確認した**。

## 素通りの扱い(道具を無視する習慣を作らないための設計)

台本は当初「検出されなかった変異」を全部同じ赤にしていた。しかし M2 / M6 / M26 の3件は
**実機 fixture 17枚に両版を当てて判定が1枚も変わらない** = そもそも到達しない緩め方だった。
ここを無条件 exit 1 のままにすると台本が**いつも赤い道具**になり、赤を無視する習慣が付く =
この台本が防ごうとしている失敗そのもの。

そこで作り替えた:

- 変異のタプルに**5つ目の要素(理由)**を書いた物だけ「未到達(注記)」として exit 0 を許す。
- 理由には必ず **(a) 覆っている別の守り** と **(b) 実機何枚で差0枚か** を書く。
- **注記つきの変異が後で検出された時は逆向きの警報**を出す(= 覆っていた守りが消えた合図)。
- 理由の無い素通りは今も赤。

さらに、注記が根拠にしている実測そのものを**実行可能な検査**に落とした
(`test/inject.test.mjs` の「現物の不変量を固定する」)。fixture が増えて前提が崩れたら
注記でなく検査が赤くなる。固定してある不変量:

| 測った物 | 値 |
|---|---|
| 桁0から始まる `─` 罫線 | 29本(入力欄のある14枚が各2本 + 許可確認画面の1本) |
| 字下げされた `─` 罫線 | **1本**。`composer-rule-in-body` の**本文の中の罫線** = 除外すべき当の物 |
| 閉じ罫線より下の行数 | 入力欄のある14枚すべてで**2行**(モデル名 + 権限モード)= 下部8行という窓の根拠 |
| 入力欄の無い画面の下部8行 | 桁0の罫線が**現れない**(`/model` 2枚は罫線0本、枠は `▔` = U+2594。許可確認の1本は下から14行目) |

## この道具が実際に嘘を暴いた例

**M24 が素通りした**。私は「欠陥3は `composer-numbered-body.txt` で再現している」と書いていたが、
測ったら番号行と入力欄が**27行離れており**近接窓(6行)の外 = あの fixture は再現していなかった。
再現する画面を撮り直して初めて赤になった。**素通り1件が、私の書いた原因説明の誤りを暴いた**。

同様に、この artifact を書く過程で自分の記述の誤りを2つ実測で潰した:
「罫線27本すべてが桁0(字下げ0本)」= 15枚時点の古い値だった(正 = 29本 / 字下げ1本)。
「選択画面には罫線が1本も無い」= `/model` 2枚だけの話を全メニューに一般化していた
(正 = 許可確認画面には1本ある。ただし下から14行目で窓の外なので結論は生き残る)。

## 未検証・持ち越し

- 実機注入の確認は **MBP でのみ** 実施。edith 上の本物の TUI へ送る一巡は次セッション。
- 引用された画面**だけ**が映って本物の入力欄が無い場合、箱の判定は引用側を指す
  (旧実装も同値なので退行ではない)。実害はペイン同一性の層が抑える。

  通してから(未実施)。

  伏字化した**(同じ26桁・全行の表示幅が不変である事を機械で確認)。関門
  `tools/check-no-pii.sh` は残し、`.git/hooks/pre-push` から実行する。範囲・対照は
  上の「PII 検査」節(8/01 に fixture 限定から追跡ファイル全体 + 全履歴へ広げ、さらに
  tailnet の入口の名前を種類2として独立に立てた。対照17枚 + 負の対照9件)。

  tailnet のホスト名・機械の構成・案件名は対象外。**緑は「公開してよい」の証明ではない**。
