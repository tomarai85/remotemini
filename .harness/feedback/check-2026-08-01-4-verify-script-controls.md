## 欠陥1 — 書いたつもりの文字列が、**こちらの機械で実行**されていた

remote へ渡す台本を二重引用符の中に組み立てていた。二重引用符の中身は ssh が送る前に
**一度ローカル(Jervis)の shell に食われる**。バッククォートはローカルのコマンド置換として
実行され、`$` も展開される。説明のつもりで書いた `` `-u` `` が Jervis 上で実行され、
その行は edith 側では**中身が消えて**届いていた。

今回は `-u` という無害な語だった。**同じ場所に `rm` や `git` を含む説明を書けばそれが走る。**
検査台本は「安全を確かめる為に一番危ない機械へ台本を送る道具」なので、ここが一番高い。

直し = 引用符付きヒアドキュメント。

```bash
ssh "$HOST" bash -s -- "$(printf %q "$REMOTE_DIR")" <<'REMOTE'
...
REMOTE
```

区切り語を引用すると一切展開されない = **書いた通りが edith に届く**。値は `$1` で受ける。

### ★以前この行に書いた診断が誤りだった

同じ場所で以前 `line 42: -u` を踏んだ時、台本の header にこう書き残していた —
「bash は台本をバイト位置で読み進めるので、走行中に編集するとずれる」。**誤り。**
再現は2行で取れる(下の C3/C4 がその再現そのもの)。バイト位置の話自体は本当なので
`main()` の包みは残すが、**根拠は別物**として header に訂正を書いた。

今夜の支配的な型 = **正しい観測を、それが支えていない結論に貼る**。これで **12件目**。

## 欠陥2 — 「他の残留物も無し」が空振りだった

片付け段の残留物確認が `ls -d /tmp/pii-ctl.* /var/folders/*/*/T/mut-* /tmp/mut-*` だった。
edith の login shell は **zsh**。zsh は一致しない glob を**致命エラー**にするので、
A が一致しない時点で `ls` ごと死に、**B と C を一度も見ないまま**次の行が
「他の残留物も無し」と出ていた。

これは今夜3度目の同じ型 —「見ていないのに **なし** と言う」。

直し = パターンを**1つずつ**見る loop。`bash -s` で shell も bash に固定したが、
**並べる書き方自体を止めた**(shell の固定は理由の半分で、書き方が壊れやすい事は残る)。

ssh / rsync を偽物に差し替え、**remote に何が届いたか**を丸ごと記録して突き合わせる。
ネットワークには出ない。

| | 見ている物 | 直す前 | 直した後 |
|---|---|---|---|
| C1 | remote 台本が書いた通りに届く(バッククォートがローカルで食われない) | **NG** | OK |
| C2 | 組み立て中にローカルで何も実行されない(`command not found` が出ない) | **NG** | OK |

負の対照の作り(C3/C4)は「壊れている物を実際に赤にできるか」の証明。旧形式の**見本**を

C5/C6 は**届いた片付け台本を現物のまま**自作の捨て dir に当てる — 期待した台本ではなく、
**実際に edith へ行く文字列**を実行するので、途中で書き換わっていれば落ちる。

## 実機注入の一巡を台本にした(`tools/live-inject-check.mjs`)

4ケース(折り返す長文 / 番号付き複数行 / 先頭行が短い複数行 / 1500字級)は 8/01 に MBP で
**手打ち**で回した。手打ちは「edith で**同じ物**を回した」と言えない。守りはコードで固定:

- 使い捨てセッション名のみ(`rc-live-<数字6桁以上>`)。実 `work` へ届く道が構造的に無い
- ペインは**自セッションから** `#{session_name}` 一致で取る(名前で当てない = §1-E)
- **Enter を送る経路を持たない**。CHOICE を見たら TmuxInjector 側が打ち切る
- 画面の写しは **repo の外**(起動バナーにアカウントのメールが載る。入れてから PII 関門に
  叩かれるのでは遅い)

ガード3件は実測で `exit 2`(セッション名 / 同名の既存 / 写しの置き場が repo の中)。
`--cases A` で1件だけ回せる(上限の消費を 1/4 に抑える為)。その検査は**引数解析の時点**で
行う — 後段に置くと打ち間違いに気付くまで起動待ちの上限(90秒)だけ待たされ、しかも
その経路は普段通らない。両方向で駆動: `--cases Z` → `落ちた: --cases に無いケース: Z(有効: A,B,C,D)`、
`--cases a,d` → 通過して tmux 段へ。

★**この道具の `tmux()` は失敗を握り潰さない**。`server.mjs` 側の runner は失敗を `""` にして
UNKNOWN へ倒す(送信側は fail-closed が正しい)が、**検査の道具が同じ事をすると失敗を
「画面が空だった」と読み違える**。同じ関数名で逆の方針を採るので、両方にその理由を書いた。
