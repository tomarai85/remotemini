# 2026-08-05 — 「検査の範囲が手書き」を数えて探した(5件目の後に2件出た)

前の記録(`check-2026-08-05-3-request-shape.md`)は、噛まれて気付いた5件目まで。
その後、**噛まれる前に数えて**同じ形を2件出した。これがこの記録の主題。

## 何を数えたか

「この検査は何を守るのか」ではなく「**この検査は自分の範囲をどこから得ているか**」で
repo 内の検査を仕分けた。手書きの一覧・固定の glob・直書きの dir を持つ物が候補。

| # | 道具 | 範囲の出所(直す前) | 実測した抜け |
|---|---|---|---|
| 6 | `tools/run-controls.sh` の照合の網 | `test/*-control*.sh ../ios/tools/*-control*.sh ../.harness/*-control*.sh` の直書き | 抜けは無かったが、門の `SCAN_SPECS` と**二重管理**。片方に dir を足せば必ず置き去りが出る |
| 7 | `tools/prove-all-controls.sh` | `glob.glob("test/*-controls.sh")` | **5 本が一度も視野に入っていなかった**(門 46 / prove-all 41) |

7 は頭に「一覧を手で持たない」と書いてある道具だった。継ぎ目は毎回探すのに、
**探す範囲**が手書き。書いてある約束と、実際に守れている範囲が違っていた。

## 直し方(両方とも同じ形)

範囲の正本を `tools/staged-controls-gate.sh` の `SCAN_SPECS`(= commit の門が見る
範囲そのもの)に一本化し、両方の道具がそこから*取り出す*。取り出せなければ空になって
**未測定(rc=2)で止まる** —— 空の網は「全部登録済み」「全部証明済み」に見えるので、
此処だけは緑でも赤でもない。

7 は範囲を広げただけでは足りなかった。`ios/tools/` の対照は既定値を `$ROOT` ではなく
**その対照が置かれた dir**から書いており、視野に入れても「既定値の形が読めない」に
落ちる。形の方も一足す事で、証明できる対照が 21 → 22 本になった。

## 対照(この記録の本体)

`test/prove-all-scope-controls.sh` 8 項目。縮める方向・伸ばす方向・門が読めない方向・
解決先まで読めている事。**伸ばす方向が本命** —— 縮める方向だけだと「生きた導出」と
「今の値とたまたま等しい定数」を見分けられない。

差替口 `RC_PROVE_ALL` に `git show HEAD:…` の旧版を渡して回した結果:

```
直した版   --- 合計: PASS 8 / FAIL 0 ---
変更前の版 --- 合計: PASS 0 / FAIL 8 ---
```

★ここが今回一番効いた手順。**最初に書いた 8 項目は、旧版に対して 3 項目が緑のまま
だった** = その3本は何も見分けていなかった:

1. 縮める方向を「`test` を残して `.harness` を削る」と書いた → 旧版は元から `test/`
   しか見ないので同じ結果になる。消す側と残す側を**両方入れ替える**のが正しい
2. `--dry` の rc=2 を見た → その道具は元から常に 2 を返す
3. 「読めない一覧に**出ていない**事」を合格にした → 視野の外の物も出ない =
   不在を合格と読む対照

修正後の木で 8/8 緑を見た時点では、この3本は完全に無症状だった。
**緑の数は対照の強さを一切示さない。旧版に対する反転数だけが示す。**

## 訂正

7 を最初に測った時、視野の外の 5 本について「4 本が差替型の継ぎ目を持つ(2/2/1/1/0)」と
書いた。これは**最も緩い正規表現の当たり数**で、`TMPDIR` や `SCRATCH` を数えていた。
守っている file を指す継ぎ目を持つのは **5 本中1本**(`sim-log-summary-control.sh`)だけ。
数え直しはしたが、数える*対象*が違った —— client を3本と書いた誤りと同型。

## 6 の対照(先に landing 済みの分)

`test/run-controls-controls.sh` に 5 項目(R24-R28)を足し、砂場に**本物の門を複製**して
縮める / 伸ばす / 読めない の3方向。旧版に対して `PASS 26 / FAIL 5`、直した版で
`PASS 31 / FAIL 0`。砂場の門を手で合成しなかったのは、門の書式が変わった時に
対照だけが古い形に対して緑を返し続けるのを避ける為。
