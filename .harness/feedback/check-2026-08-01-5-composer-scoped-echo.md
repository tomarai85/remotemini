# 検査記録 2026-08-01-5 — 届いていない本文に `verified` を返していた(唯一の fail-open)

対象 = `rc-backend/src/inject.mjs`(送信の echo 相)/ `rc-backend/test/inject.test.mjs`
(画面の作り方を7本作り替え + 回帰1本)/ `rc-backend/test/mutation-controls.py`(M34)。

きっかけ = 前の記録(`check-2026-08-01-4`)の最後に自分で書いた「**送信経路は依然として未駆動**」。
偽 TUI の出来が悪くて回せなかった、で止めずに偽物を作り直した。

## 何を見つけたか

偽物 = `scratchpad/fake-composer.sh`。空行30本 + 罫線 + `❯ ` + 罫線 + `Fake 0.0` を描いて
`exec sleep 600`。**入力欄の箱の構造だけを満たし、stdin は一切読まない**。
本物の tmux 越しに、本物の `TmuxInjector.send()` で本文を送った結果:

```
| A | 折り返す長文(1行) | 100 | sent delivered=verified | echo=3ms clear=3ms |
```

相手は `sleep 600`。**一文字も届いていないのに「届いた」と報告している。**

この層の欠陥1〜8は全部「送れない / 確認できない」側に壊れる — 害はあるが嘘はつかない。
**9件目のこれだけが向きが逆**で、電話には「送れました」と出たまま何も起きない。
運用上いちばん高くつく壊れ方(Tom は送ったつもりで待つ)。

## 真因 — 規約の文言とコードが一致していなかった

`send()` の echo 相は印(本文末尾12字)を **画面全体** で数えていた。
設計文書(`DESIGN.md` の reason 表)も関数の説明も「本文が**入力欄に**載っていなければ
`composer-mismatch`」と書いてあるのに、コードは「画面のどこかに出たか」しか見ていない。

偽物へ `send-keys -l` した文字は、相手が読まないので tty のエコーとして**箱の下**に出る。
→ 画面全体では印が増える → 「載った」→ Enter → 送信後の確認は入力欄を見て
「空 = 取り込まれた」→ `verified`。**3つの観測が全部正しく動いて、結論だけが嘘になる。**

直し:

```js
const seenBefore = countOf(norm(composerText(before) ?? ""), probe);   // baseline も箱の中
...
const inBox = composerText(t);
if (inBox !== null && countOf(norm(inBox), probe) > seenBefore) return "echoed";
```

入力欄の外に出た本文で Enter を押す理由が無いので、構造的に箱の中へ限ってよい。

## ★追記(22:55)— この直しが**別の守りの足場を外していた**

「画面全体には字下げが残る」という**副作用**の方だった。

**直しは正しい。だが正しい直しが守りを1つ黙って外す事がある。** 気付けるのは変異検査だけ。

### 正規化が実機で載っている事(実測 · 端末幅120 · 本物の Claude Code TUI)

**最終行が印(12字)より短い本文は長文のおよそ2割**。その2割は正規化が無いと
「本文は入力欄に在るのに `composer-mismatch`」= 永久に送れない(fail-closed だが送れない)。

### CHOICE の打ち切りも実機で駆動(この層で最後の未駆動経路)

選択画面の作り方 = **`/model` のピッカー**(Escape だけで閉じる = 完全に戻せる)。
信頼確認ダイアログは「信頼する/しない」という取り返しの要る判断なので使わない。
台本 = `scratchpad/live-choice-abort.mjs`(Enter を送る箇所は `/model` を打つ1つだけ)。

```

OK 画面を変えない(送信前後の写しが同一)   OK 本文が画面に出ていない   OK まだ選択画面のまま
OK Escape で入力欄に戻る(412ms, SENDABLE)                                    → exit 0
```

台本は使い捨てで終わらせず `rc-backend/tools/live-choice-check.mjs` に入れた(手打ちだと
次の機械で「同じ物を回した」と言えない — `live-inject-check.mjs` と同じ理由)。

**負の対照つき**: `menuAt` を殺した木で走らせると `選択画面が出ない(state=UNKNOWN)` で
**exit 1**。緑が空っぽでない事を確かめてある。

★その負の対照が**台本自身の欠陥**を1つ出した: 準備段の打ち切りを `try` の中の
`process.exit(1)` でやっていて、**`finally` が走らない** = 建てた使い捨てセッションが

直し = `failed = true; return;` で `finally` を必ず通し、終了コードは `main()` の外で決める。
直した後: 負の対照 = exit 1 + 片付け不在確認 / 本番 = 7項目 OK + exit 0 + 残留なし。

  4ケース中、返答まで観測できたのは A だけ。
- run8/run9(edith 一巡)の木は **M29 の回帰を含まない**。run10 で取り直すまで edith 側の
  変異結果は「素通り1」のまま。
- 欠陥9は「規約の文言とコードが違う」型だった。同じ型が他に無いことは証明していない
  (機械では測れない。`reason` 表の4行を一度読み直したのが今回できた全部)。
- M29 の件が示したのは「**変異が素通りに変わる事がある**」= 変異一巡は直すたびに
  取り直さないと意味を失う。前回の値を再利用してはいけない。
