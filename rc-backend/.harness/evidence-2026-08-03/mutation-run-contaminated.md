# 197 件の変異走行が汚れていた(2026-08-03)

結論を先に: **15:12 に始めた 197 件の走行は測定として読めない。3 時間 17 分走った所で
止めて、根本の欠陥を直してから回し直す。**

## 何が起きたか

`test/mutation-controls.py` の `copy_tree()` は、変異 **1 件ごとに** その時点の
作業ツリーを写していた(開始時に一度写して固定していなかった)。197 件 x 約 65 秒 =
3 時間半かかるので、その間に同じ repo を触れば、前半と後半で**違う木を測る**。

実際に触った。走行開始(15:13:33)より後に、指紋の範囲
(`src` / `test` / `tools` / `package.json`)の中で 10 file が動いている:

## なぜ「遅いだけ」で済まないか —— 壊れ方が**緑の方向**に出る

新しく置いた `tools/mutation-verdict.sh` の注釈が、この repo 自身の散文規則
(`test/no-linerefs.test.mjs`)に触れていた。破っていたのは 2 つ:

- repo の外の file を**行番号つき**で引いていた
- その file 名を backtick で引いていた(repo 内に実在しないので「置き去りの参照」と読まれる)

結果 `npm test` は `pass 534 / fail 2` になった。変異の判定は

```python
if ufail or efail:
    verdict = "検出"          # ← 変異を殺したから、ではない
else:
    verdict = "★素通り"
```

なので、**この file が置かれて以降の変異は全部「検出」と記録される**。変異を殺したからでは
なく、変異と無関係な検査が落ちていたから。つまり:

- 素通り(= 検査に穴が在る所)が**丸ごと隠れる**
- 要約は「素通りした変異: なし」と書く = **緑と読める**
- 走行の log の進捗行は同じ形のまま並ぶので、**境目が外から見えない**

この repo が潰す為に在る 3 つの偽の緑(砂場が薄い / 変異が空振り / 判定文の当て所違い)の
**4 つ目**。今回の形は「測っている最中に測定対象を書き換えた」。

## 直した所

`test/mutation-controls.py`:

1. **開始時に一度だけ写して凍結**し、以後の変異はその凍結から写す。
   走行中に手元を編集しても測定が汚れない(3 時間半のあいだ編集を禁じるのは非現実的)。
2. 終了時に手元の木が動いたかを見て、動いていたら**動いた file 名を並べて**
   「この報告は走行開始時の木を説明する」と明示する。
   指紋(hash)ではなく名前を出すのは、hash は「何かが動いた」しか言わないから。
   名前が出れば、それが測定に効く変更かをその場で判断できる。

`tools/mutation-verdict.sh`:

3. 規則違反の注釈を書き換えた。行番号ではなく**綴りの目印**
   (`min(max(int(t.get("verify_timeout_s")` で始まる行)を書く。`npm test` は 536/536 緑。

なお `tools/mutation-verdict.sh record` の方は**最初から前後で指紋を採って**いて、
走行中に木が動いたら記録を拒む(exit 2)。守りは在ったのに、3 時間半かかる本走行が
その道具を通っていなかった、というのが今回の穴。

## 対照(この直しが効いている事の証拠)

`scratchpad/freeze-probe.sh` —— 走行中にわざと手元の木を赤にして、

- 走行が汚れない(凍結が効いている)
- 要約が「手元の木が動いた」と名指しで言う

の 2 つを見る。見分けに `M85`(**注記つき** = 到達しないと実測済みで、正常なら
「未到達(注記)」)を使う。凍結が破れて手元の赤を拾えば「★注記を外せる」に化けるので、
そこが discriminator になる。普段から検出される変異(`M1` 等)ではどちらでも「検出」に
なって区別が付かない —— 最初に `M1` で測ろうとして、測れない事に気付いた。

緑としても赤としても読まない**。汚染は素通りを隠す方向なので、
「素通りが出ていない」事から言える事が何も無い。回し直す。
