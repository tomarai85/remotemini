Yes. Keep `/Users/edith/rc-backend` as a real directory and keep the plist unchanged. I would not pay the bootout/bootstrap cost for a symlink flip.

Atomic replacement is beneficial, but not load-bearing here. However, the six steps need one additional safeguard: prevent launchd from starting Node while either forward or rollback rsync is modifying the live tree.

QB — Failure modes

Step 3 is safe under your stated assumptions: the tree is immutable while running and all mutable state lives elsewhere. Open modules do not make the snapshot inconsistent.

Harden it as follows:

- Acquire a deployment lock to prevent concurrent deploys.
- Copy into a `.partial` snapshot, check completion and disk space, then rename it to its final `prev-*` name.
- Exclude `.git/` from the snapshot too. Otherwise you duplicate someone else’s repository into every release.
- Do not derive `oldrev` from the live `.git`; that hygiene commit is not deployment provenance.

Step 6 is the weak point as written. After failed verification:

- The new process might still be running and lazily reading files.
- KeepAlive might launch another process during the rollback rsync.
- A machine reboot or deployment-script crash during step 4 means step 6 never runs automatically.

Add an external maintenance marker that the launch script checks before executing Node. While the marker exists, the launcher should wait rather than restart-loop. Set it before step 4 and retain or recreate it throughout rollback. This requires changing the launcher once, but not the plist.

Also:

- Do not use rsync `--inplace`; normal temporary-file-and-rename behavior avoids individually truncated files, although the overall tree remains mixed-version during transfer.
- Verify the deployed build/revision, not merely “returns 401.” Otherwise a wrong or old build can pass.
- Apply the same PID/listener/readiness checks after rollback.
- Audit for lazy imports, runtime file reads, templates, or spawned scripts; “modules are resident” is safe only if none exist.

So: accept the directory-based deployment, preserve the foreign `.git`, and add a launch interlock. The corrected `.git` is not a valid recovery source; the verified release snapshot is.
