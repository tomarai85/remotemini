# `choice-reply` — 自分の diff を読み直して出た欠陥 3件(2026-08-03、変異走行の待ち時間に)

Codex の第2意見(`codex-choice.txt`)を当て終えた後、**その当て自体**を読み直した記録。
出典は自分の diff だけで、外部指摘ではない。3件とも「試験は全部緑のまま」通っていた。

## F1 打鍵の記録が `tmux.run` の**後**に在る

```js
this.tmux.run(keyArgs(pane, key));
this.#choiceSent.set(pane, now);   // ← ここ
```

`tmux.run` が投げると指紋が記録されないまま抜ける。撃ち直しが通る = 二度打ちの穴が
**例外路にだけ**残っていた。「結果が分からない時は断る側」なら、記録は**打とうとした時点**。

## F2 ★止めを**解除する口が無い**(機能欠陥。安全ではなく可用性の側)

`#choiceSent` は `Map<pane, digest>` で、`set` はあるが `delete` がどこにも無かった。
帰結: **同じ形のメニューへはペインごとに生涯1回しか打てない**(別の指紋を打って
上書きするまで永久に `choice-already-sent`)。

- `select-model` はカーソル位置が指紋に入るので、選び直すと指紋が変わって実際には
  当たりにくい。だが**それは偶然であって設計ではない**。カーソルが動かないメニューが
  1つ増えた瞬間に、その形は二度と答えられなくなる。
- 止めの目的は「**結果が分からない**間に撃ち直させない」事。画面が動いたのを
  **観測した**時点で結果は分かっている = 目的は果たされている。だから消す。
- 消す所は2つ、どちらも**観測に基づく**:
  1. 冒頭で「そのペインはもうメニューに居ない」と分かった時
  2. poll の後、打鍵で画面が動いた(`left` / `changed`)時
- `unverified`(動いていない)の時**だけ**持ち続ける。ここが止めの本体。

★覆る条件: 実機で「解除の直後に同じ指紋のメニューが出て、溜まっていた1発目と2発目が
両方着弾した」が**1回でも観測されたら**、解除をやめて時間ベースの止めへ倒す。

## F3 但し書きが「撃ち直せば通る」と読める

`NOTE_AFTER_CHOICE.unverified` の末尾が「画面を取り直して確認してください」。
取り直しても指紋が同じなら断られる。**断られるのが意図**である事を文面に出す。

## この3件で足す検査・変異

- 検査「★動いたのを見た後は、同じ指紋へまた打てる」= F2 の解除側。
  既存の「★★同じ指紋へ二度は打たない」(= 止め側)と**対**になる。
- 変異 **C19** 動きを見ずに無条件で解除する(= 危険な向き)→ 止め側の検査が赤
- 変異 **C20** 一度も解除しない(= 使えなくなる向き)→ 解除側の検査が赤

**なぜ両方要るか**: 片側だけだと「常に解除」も「常に保持」も、どちらか一方の検査で
緑のまま通る。止めは条件付きなので、**条件の両側**に対照が要る。
