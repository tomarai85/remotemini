## 2. ★`git bisect` が**嘘の犯人**を指した（この夜で一番危ない発見）

`bisect` は **1 commit につき 1 走**しか測らない。揺らぐ検査に当てると、
「その commit で偶々落ちた」を「その commit で壊れた」と読む。

- `bisect` の判定: `69fd70d` が first bad commit。
- 同じ `69fd70d` を **5 回**回した実測: **FAIL 1 / PASS 4**。

→ 犯人ではない。**混入した commit は存在しない。この検査は最初から競走だった。**
一般化: **揺らぐ検査を `bisect` に掛けてはいけない。** 掛ける前に同一 commit を N 回回して
判定が安定する事を先に確かめる。

## 3. 揺らぎの正体 —— 暗黙の壁時計依存（この repo の既知の病、12-h と同じ型）

同じ commit・同じ木で、置き場所を変えるだけで結果が変わった:

| 走らせた場所 | 赤/走行数 |
|---|---|
| `~/Infra/mobile-work/rc-backend`（本物の木） | **9 / 10** |
| `/private/tmp` の写し | **1 / 6** |

「緑」が意味していたのは *性質が成り立つ* ではなく *機械が偶々速かった* だった。

### 機構（切り出して単体で測った実測値）

偽ワーカーの構造は 親 → 孫（孫が親の pipe を握ったまま残る）。

| 出来事 | 時刻 |
|---|---|
| 親の `exit` | 約 **27ms** |
| 孫が本文を書く（旧: `time.sleep(0.35)`） | 約 **400ms** |
| `close`（孫が pipe を放す） | 約 **404ms** |

サーバの event loop がこの **370ms の窓**の何処かで詰まると、
既に読める状態の stdout が `exit` の callback より先に処理され、ring の `seq` の順序が反転する。
`seq` は到着順（`worker.mjs` の `_emit` が同期で `ring.push`、`ring.mjs` が `nextSeq++`）なので
測定としては正しい。**間違っていたのは「何に賭けたか」の方**。

## 4. 直し方 —— 消音ではなく、賭けを構造から外す

§2.18-10(2)（死の合図は `close` ではなく `exit`）を本当に見分ける条件は
**「孫が pipe を握ったままで `worker_closed` が届くか」**。
`close` を合図にしている実装では構造的に起こり得ない事象なので、これは真の弁別子である。
そして**孫がいつ書くか**は、この弁別子には要らない。

そこで孫の書き込みを**検査側の合図**（`death-gate` file）で握った:

- `RC_E2E_DEATH_GATE` が置かれるまで孫は書かない（上限 20s）。
- 検査は「孫が握ったまま `worker_closed` が来る」を先に確かめる。
- その後で検査が合図を置き、**以降に届いた本文は確実に死の後**という順序で
  「死後の本文も ring から失われない」を確かめる。

壁時計は式から消えた。**環境が速かろうが遅かろうが順序は検査が決める。**

旧い検査文（「孫が pipe を握ると本文は worker_closed の**後**に届く（採った取引の代償）」）は
削除して弁別子に置き換えた。合図を空にすると孫は待たずに即書くので (2) は落ちる
= **合図が効いている事の栓**。

## 8. 途中で自分が出した**間違った測定**（訂正込みで残す）
